# Runbook — What Must Never Be Committed to GitHub

This is the authoritative list of files, values, and artifacts that must never
be pushed to the `irexpro` repository (or any fork/clone of it). The
`.gitignore` excludes most of these automatically; this document exists so
operators and engineers know **why** each is excluded and can spot-check before
pushing.

---

## 1. Files that must never be committed

| Path / pattern | Why | `.gitignore` entry |
|---|---|---|
| `apps/api/.env` | Contains real DB password, JWT secret, broker encryption key, payment provider secret keys | `.env` + `.env.*` (with `!.env.example` exception) |
| `services/ai-engine/.env` | Contains real Redis password, internal API key | `.env` + `.env.*` (with `!.env.example` exception) |
| `apps/api/dist/` | Build output — regenerated on every build; tracking it causes merge noise and ships stale code | `dist/` |
| `**/node_modules/` | Dependencies — installed via `pnpm install`, not committed | `node_modules/` |
| `services/ai-engine/.venv/` | Python virtualenv — installed via `pip install` | `.venv/` + `venv/` |
| `**/__pycache__/` | Python bytecode cache | `__pycache__/` + `*.pyc` |
| `coverage/` | Test coverage output | `coverage/` |
| `.next/`, `.turbo/`, `.cache/`, `build/` | Build caches | individual entries |
| `*.log`, `logs/` | Application logs (may contain request data, internal IDs) | `*.log` + `logs/` |
| `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.crt`, `*.csr` | TLS keys/certs | individual entries |
| `id_rsa*`, `id_ed25519*` | SSH private keys | individual entries |
| `*.egg-info/` | Python package metadata (auto-generated by `pip install -e .`) | not in `.gitignore` — see §3 |
| `.DS_Store`, `Thumbs.db` | OS artifacts | individual entries |
| `.vscode/`, `.idea/` | Editor configs (may contain local paths/secrets) | individual entries |

### 2.1 What placeholders ARE acceptable in committed files

Only non-real, obviously-fake placeholders are acceptable in `.env.example`,
docs, and tests:

- `CHANGE_ME_*` (e.g., `CHANGE_ME_TO_LONG_RANDOM_SECRET_IN_DEV`)
- `PLACEHOLDER` (e.g., `sk_test_PLACEHOLDER`)
- `dev_internal_key_change_me`
- `REPLACE_WITH_STRONG_PASSWORD` (in runbook SQL examples)

These cannot be used to authenticate against any real system. If you find
yourself typing a real-looking value into a committed file, stop and put it in
`.env` instead.

## 3. Pre-push self-check

Before every `git push`, run:

```bash
# 1. Confirm no .env files are staged
git diff --cached --name-only | grep -E '\.env$' && echo "BLOCK: .env staged" || echo "OK: no .env staged"

# 2. Confirm no dist/node_modules/.venv staged
git diff --cached --name-only | grep -E '(^|/)(dist|node_modules|\.venv)/' && echo "BLOCK: build artifact staged" || echo "OK: no build artifacts"

# 3. Scan staged diff for real-looking secrets (tune patterns to your stack)
git diff --cached | grep -iE 'sk_live_|sk_test_[a-zA-Z0-9]{20,}|whsec_[a-zA-Z0-9]{20,}|ghp_|eyJhbGciOi' && echo "BLOCK: real-looking secret in diff" || echo "OK: no real-looking secrets"

# 4. Confirm no CHANGE_ME/PLACEHOLDER remains in real .env (only allowed in .env.example)
grep -rE 'CHANGE_ME|PLACEHOLDER|dev_internal_key' apps/api/.env services/ai-engine/.env 2>/dev/null && echo "BLOCK: placeholder remains in real .env" || echo "OK: real .env has no placeholders"
```

If any check prints `BLOCK:`, do not push. Fix the issue first.

## 4. The `.env` vs `.env.example` rule

| File | Purpose | Committed? | Contains real secrets? |
|---|---|---|---|
| `.env.example` | Template showing required variables | **Yes** | **Never** — only `CHANGE_ME_*` / `PLACEHOLDER` |
| `.env` | Real runtime configuration | **Never** | **Yes** — real passwords, keys, tokens |

The `.gitignore` enforces this:
```
.env
.env.*
!.env.example
```

If you accidentally `git add .env`, unstage it immediately:
```bash
git rm --cached apps/api/.env services/ai-engine/.env
```
The file stays on disk (your app still reads it) but is removed from the index.

## 5. What to do if a secret was committed

If a real secret was pushed to any branch (even a feature branch):

1. **Rotate the secret immediately.** Assume it is compromised the moment it
   touched git history. Generating a new secret is faster and safer than
   rewriting history.
2. Update the real `.env` on every server with the new secret.
3. Restart the affected services (`pm2 restart` or `systemctl restart`).
4. Audit logs for misuse during the exposure window.
5. Consider history rewriting (`git filter-repo` / BFG) ONLY if the secret
   cannot be rotated (e.g., a third-party's static key). Rewriting history
   forces a force-push and is disruptive — prefer rotation.

For the `irexpro` repository specifically, the secrets that would be most
damaging if leaked are:
- `BROKER_ENCRYPTION_KEY` (decrypts every broker credential at rest)
- `JWT_SECRET` (can forge any user's auth token)
- `PAYSTACK_SECRET_KEY` / `STRIPE_SECRET_KEY` (can initiate refunds, view
  customer data)
- `METAAPI_TOKEN` (can access every connected MetaTrader account)
- `NESTJS_INTERNAL_API_KEY` (can forge AI signals that enter the risk/execution
  pipeline)

Rotate any of these within minutes of a suspected leak.

## 6. Python `egg-info` artifacts

`pip install -e .` in `services/ai-engine/` generates
`irexpro_ai_engine.egg-info/` metadata. This directory is currently **not** in
`.gitignore` and shows up as modified after a local install. It should be
added to `.gitignore` (see Sprint 19 `.gitignore` update) and never committed —
it is auto-generated, environment-specific, and carries no real secrets but
creates noise in diffs.
